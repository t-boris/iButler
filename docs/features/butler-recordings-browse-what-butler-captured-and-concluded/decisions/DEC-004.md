## Context

Recordings includes generated images and Display history under an owner-only visibility requirement, while the existing Display policy allows valid cards to remain visible without a private-session gate.

## Alternatives

1. Apply owner-only visibility in Recordings while leaving the existing Display policy unchanged.
2. Apply owner-only visibility in Recordings and separate Display rules by material type.

## Decision

Show generated images and Display history only to the verified owner, both in Recordings and on Display.

## Reason

The team selected a consistent owner-only rule for these materials across both interfaces.

## Consequences

Update REQ-005 and the existing Display visibility policy so both interfaces enforce verified-owner access for generated images and Display history. Define acceptance criteria and access behavior for unverified users.

## Implementation

Recordings, the gallery and Display snapshots/actions now require verified-owner access. Temporary verification loss hides history; hard closes retain the existing clearing rule.
