## Finding

All GitHub Python/Node suites and release builds passed, but the native UI test trapped before producing a report. LaunchServices did not fix it. A debugger backtrace from run 40632362020 identified a real AppKit layout feedback loop: `Panel.saveFrame` called `setFrame` inside `windowDidResize`, repeatedly clamping to the runner’s 1024×681 visible area while the window/content minimum was larger. AppKit raised an exception for excessive layout passes.

## Resolution

Make resize/move persistence record the actual frame without resizing during layout notifications. Bound user-initiated resizing in `windowWillResize`, respecting the window’s minimum when a display cannot fit it. Keep initial production restore clamping, and use an explicit logical canvas for synthetic tests independently of the runner’s physical display. Add a native regression for side-effect-free frame persistence and the small-display minimum. Keep the complete native verification report as a required CI gate; do not skip the UI tests or hide a crash.

## Local verification

The complete native suite passes all 264 checks after this repair, including the new small-display/frame-persistence regression. The full exact-source release gate and both GitHub jobs remain required before merge/deploy.
