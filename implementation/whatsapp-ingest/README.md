# Пассивное чтение WhatsApp

Исправление инцидента 14 октября 2026 года: входящие сообщения из личных
WhatsApp-чатов запускали разговорного агента. При ошибке модели шлюз отправлял
сообщение об ошибке собеседнику от номера Бориса. Запрет в промпте не защищал
от ошибок, возникающих до выполнения инструкций агентом.

## Поведение после исправления

- Существующая проверка разрешённых отправителей остаётся перед обработчиком.
- Обработчик сразу передаёт входящее сообщение в `lib/inbox.buffer_message` и
  завершается. Команды, реакции, маршрутизация сессий и вызовы модели обходятся.
- Вызов Python получает JSON через stdin, без shell и текста сообщения в argv.
- Сохраняются идентификатор сообщения, направление, отправитель и местное время.
  Повторная доставка использует существующий стабильный ключ дедупликации.
- Запись ожидается до подтверждения обработки в существующем журнале приёма.
  Ошибка записи остаётся локальной; перехода к разговорному агенту нет.
- На уровне сокета запрещены исходящие тексты, медиа, опросы и реакции.
  Присутствие допускается только `unavailable`; печатание и прочтение подавлены.
- Удалена привязка WhatsApp к Butler. Дополнительно действует
  `session.sendPolicy.rules: [{ action: "deny", match: { channel: "whatsapp" } }]`.
- `sendReadReceipts: false`, `debounceMs: 0`: каждое сообщение сохраняет свой ID.

Instagram отсутствует в конфигурации проверенного шлюза; это исправление
относится к подключённому WhatsApp. Telegram-userbot продолжает наполнять ту же
очередь. Подключения Telegram-ботов работают.

## Установка и обслуживание

Проверенная версия: OpenClaw и `@openclaw/whatsapp` **2026.5.27**.
Применяется локальный патч двух сборок WhatsApp-плагина: monitor и session.
Для этой версии штатный `message_received` является наблюдательным хуком и
не предоставляет нужной ранней остановки до реакций и запуска агента.
Описание хуков: [официальная документация OpenClaw](https://docs.openclaw.ai/plugins/hooks).

Рабочая копия установщика и проверки запуска расположена в
`~/.openclaw/tools/whatsapp-ingest/`; запуск службы не зависит от папки проекта.
Обёртка службы `~/.openclaw/service-env/ai.openclaw.gateway-env-wrapper.sh`
выполняет `preflight.py` перед запуском шлюза. Если обновление стёрло патч или
изменилась защитная конфигурация, проверка отключает WhatsApp, позволяя остальным
каналам запуститься. Патч не применяется автоматически к незнакомой версии.

После обновления сначала отключить WhatsApp, затем применить и проверить патч:

```sh
/opt/homebrew/bin/openclaw config set channels.whatsapp.enabled false --strict-json
python3 ~/.openclaw/tools/whatsapp-ingest/install.py
python3 ~/.openclaw/tools/whatsapp-ingest/install.py --check
/opt/homebrew/bin/openclaw config validate
```

Включать канал только после успешных проверок. Смена параметров может сама
перезапустить шлюз; перед дополнительным перезапуском дождаться завершения
автоматического рестарта и проверить `gateway status`.

Конфигурационный патч в корне проекта: `openclaw.patch-wa-passive.json5`.
Он намеренно оставляет WhatsApp отключённым до установки защиты.

## Проверка

```sh
node --test implementation/whatsapp-ingest/tests/ingest-only.test.mjs
python3 -m unittest discover -s implementation/whatsapp-ingest/tests -p 'test_*.py'
```

12 проверок: блокировка сообщений/медиа/реакций/статусов/прочтения, сохранение
в изолированной копии реального inbox, дедупликация пачки, безопасная передача
кавычек и shell-синтаксиса, граница трёх дней, таймаут/ошибка записи,
раннее завершение установленного обработчика и отключение канала при утрате
защиты. Тесты не отправляют сообщений и не пишут в рабочую очередь или vault.

## Восстановление службы

При перезапуске выявлена отдельная поломка Homebrew Node.js 24:
`Library not loaded: .../libsimdjson.33.dylib`. Служба переведена на проверенный
Node.js 22.22.3 по абсолютному пути. Старый plist, обёртка, конфигурация,
AGENTS.md/CLAUDE.md и изменённые JS-сборки сохранены перед правкой.
Путь к версии Node.js необходимо сохранять при обслуживании nvm.

Откат старой конфигурации возвращает опасную маршрутизацию. При необходимости
отката сначала отключить WhatsApp и оставить его отключённым.
